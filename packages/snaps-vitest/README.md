# @metamask/snaps-vitest

A Vitest environment and matchers for end-to-end testing MetaMask Snaps. This
package is a Vitest port of [`@metamask/snaps-jest`](../snaps-jest), and provides
the same end-to-end testing API:

- A Vitest environment that starts the built-in Snap server and exposes
  `installSnap()`.
- The Snaps matchers (`toRespondWith`, `toRespondWithError`,
  `toSendNotification`, `toRender`, `toTrackError`, `toTrackEvent`, and
  `toTrace`).
- The `installSnap`, `getMockAccount`, `getStateFromAccount`, and
  `getStateFromAsset` helpers.
- The Snap test types re-exported from `@metamask/snaps-simulation`.

The public API is intentionally identical to `snaps-jest`, so existing test
bodies need only test-runner changes (`jest.*` to `vi.*`).

## Requirements

- Node.js `^20` or `>=22`
- Vitest `^3.1.1`

## Usage

Add the preset to `vitest.config.ts`:

```ts
import { defineConfig } from 'vitest/config';
import { getSnapsVitestConfig } from '@metamask/snaps-vitest';

export default defineConfig(
  getSnapsVitestConfig({
    // Optional: makes `describe`, `it`, `expect`, and `vi` global.
    globals: true,

    // Same options as Jest's `testEnvironmentOptions`.
    // `server.root` defaults to `process.cwd()`.
    environmentOptions: {
      server: {
        root: process.cwd(),
      },
    },
  }),
);
```

`getSnapsVitestConfig` also configures the Snaps JSX runtime
(`@metamask/snaps-sdk`, production mode) so JSX in tests, such as arguments to
`toRender`, behaves like it does under `ts-jest`. If you prefer to set up Vitest
manually, spread the lower-level `snapsVitestPreset` into `test` and set the
same `esbuild.jsx` options yourself.

Write tests exactly as with `snaps-jest`:

```ts
import { installSnap } from '@metamask/snaps-vitest';

describe('My Snap', () => {
  it('responds with bar', async () => {
    const { request } = await installSnap();

    const response = await request({
      method: 'foo',
      params: ['bar'],
    });

    expect(response).toRespondWith('bar');
  });
});
```

### Environment options

| Option           | Default         | Description                                                          |
| ---------------- | --------------- | -------------------------------------------------------------------- |
| `server.enabled` | `true`          | Start the built-in HTTP server.                                      |
| `server.port`    | `0`             | Port for the server. `0` picks a random available port.              |
| `server.root`    | `process.cwd()` | Directory containing `snap.manifest.json` and the built Snap bundle. |

These are passed through `test.environmentOptions`, not
`testEnvironmentOptions`.

## Migrating tests from `@metamask/snaps-jest`

1. Replace the Jest preset with `snapsVitestPreset` and
   `test.environmentOptions`.
2. Replace `@jest/globals` imports with `vitest`.
3. Replace `jest.fn`, `jest.spyOn`, `jest.mock`, and `jest.requireActual` with
   their `vi.*` equivalents.
4. `vi.mock` is hoisted like `jest.mock`; use `vi.hoisted()` for variables
   referenced inside a mock factory.
5. Test bodies and Snap assertions do not need to change.

The matcher TypeScript declarations extend Vitest's assertion interface.
Importing anything from `@metamask/snaps-vitest` augments `expect`.

## Known differences from Jest

- When a `beforeAll` hook fails, Jest marks every test in the suite as failed,
  while Vitest skips the remaining tests. This is a runner difference, not a
  Snap behavior difference. The executing tests and assertions behave
  identically.
- Parameterised test names generated by `it.each` with object arguments are
  formatted differently by each runner.
- Snapshot formatting may differ between Jest and Vitest serializers.
- Integration tests that share a chain can be order-sensitive. Use Vitest's
  `sequence.sequencer` or `fileParallelism: false` to pin the file order.

## Development

```sh
yarn workspace @metamask/snaps-vitest run lint
yarn workspace @metamask/snaps-vitest run test
yarn workspace @metamask/snaps-vitest run build
```

## Layout

```text
src/
  environment.ts          Vitest environment (server + installSnap)
  setup.ts                Registers the matchers
  matchers.ts             Snaps matchers
  helpers.ts              installSnap and mock account helpers
  options.ts              Environment option validation
  global.ts               Vitest matcher type augmentation
  internals/              Server, logger, account helpers
  test-utils/             Test-only helpers and the fixture Snap
test/
  e2e.test.ts             End-to-end smoke test using the fixture Snap
```
